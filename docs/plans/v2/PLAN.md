# PLAN v2: 本番運用できる監視ツールへ（案）

目標: 「機能は強力、構築は簡単」。デモ用の現スタックを、実機につないで常時運用できる compose 一式に育てる。

## 決定済み（オーナー回答 2026-10-25）
- パケット解析: キャプチャ（任意で有効化）と保存済み pcap の解析の両方に対応
- 認証: 当面なし。ただし後から認証を差し込める構え（認証プロキシの差し込み口、役割の受け口）を用意
- 優先機能: 本番構成と導入の手軽さ / アラート通知 / 履歴再生と証跡出力 / ネットワーク図と相関分析
- 本番ホスト: Linux（Raspberry Pi / 小型PC）。arm64 と amd64 の両方で動くイメージ、Pi 向けの省資源な既定値
- フェーズ順: P1 → P2 → P3 → P4 → P5（承認済み）

## フェーズ
| # | 内容 | 主な成果物 |
|---|---|---|
| P1 | 本番構成と導入 | compose の profile 分け（`demo` / `prod` / `capture`）、実機用 snmp_exporter（SNMPv3 authPriv）、syslog 受信（LAN 側 UDP）、初期設定コマンド（`.env`・機器台帳の生成、SNMP 疎通・syslog 受信テスト）、healthcheck・再起動方針・リソース上限・ログローテーション・イメージ固定、バックアップ/復元スクリプト、更新手順、認証の差し込み口（前段リバースプロキシ） |
| P2 | アラート通知 | Alertmanager、通知先（メール / Slack / Discord / Webhook。LINE は Messaging API）、抑止（silence）・確認（ack）の UI、通知テスト |
| P3 | パケット取込と解析 | `capture` profile のキャプチャ用コンテナ（既定は無効、BPF フィルタ、リングバッファ、容量上限）、実フロー生成と GeoIP（既定は DB-IP Lite）でデモの通信先データを置き換え、pcap 解析画面（パケット一覧・プロトコル内訳・会話・端点・パケット詳細と16進表示・表示フィルタ）。解析はサーバ側の隔離コンテナで tshark、上限付き、伏せ字を適用 |
| P4 | 履歴再生と証跡 | PLAYBACK モード（時刻スライダ・再生速度・「履歴再生」の固定表示）、アラートや選択期間の証跡出力（クエリ・データ・版情報を zip） |
| P5 | ネットワーク図と相関 | 機器台帳（＋取れれば LLDP）からのトポロジー図を地球儀と切替表示、端末×通信先の急増検出と、同時期のアラート・ログを並べる「原因候補」パネル（因果は断定しない） |

各フェーズ: 仕様確認 → 実装 → Claude レビュー＋Codex レビュー → PM の動作確認 → コミット。
PC 負荷の制約（コンテナは確認時のみ起動、ブラウザは同時 1 つ）は継続。

## 制約・リスク
- 実機の情報（RTX/WLX の FW、SNMP 設定、syslog 形式、配線・VLAN）は未採取。P1 は「設定すれば動く」状態までで、実機での検証はオーナー環境で行う
- ミラーポートの設定変更は仕様 G4 のとおり手作業・要承認。ツールからルーター設定は変更しない
- キャプチャは Linux ホストの host network が前提。Windows の Docker Desktop では LAN 側のパケットを直接取れない
- GeoIP: MaxMind はアカウントとライセンスキーが必要なため既定は DB-IP Lite（CC BY 4.0、表示義務あり）
- 認証なしの間は、既定で 127.0.0.1 にのみ公開。LAN 公開は明示設定＋警告表示
