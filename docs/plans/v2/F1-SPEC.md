# F1 仕様: Grafana なしで足りるコマンドセンター（推移・ログ検索）

親計画は `docs/plans/v2/PLAN.md` です。

オーナーの決定（2026-10-28）は次の 3 点です。

- コマンドセンターだけで監視の用が足りるようにする
- Grafana は任意の追加機能にし、既定では動かさない
- 全文のログ検索は Loki のまま行う（Elasticsearch は入れない）

## 受入条件

### 1. 推移の画面

- 指標の種類は mask-api の許可リストから選びます。
  - IF の通信量 (bps)、エラー、破棄 (drop)
  - 機器の UP と稼働時間、WAN の利用率
  - 通信先ごとの量 (国、ASN、LAN の端末)
  - 無線の端末数 (取れるときだけ)、パケット取込の状態
- 範囲は「機器」「IF」「通信先」で絞ります。種類ごとに使える絞り込みは許可リストで決めます。
- 期間は 1h / 6h / 24h / 7d / 30d と、開始・終了の指定から選びます。
  - グラフをドラッグすると、その区間に拡大します。「拡大を戻す」で前の期間に戻ります。
  - 刻み (step) はサーバーが決め、1 系列あたり 600 点以下にします。
- 系列は複数を重ねて描き、凡例のボタンで表示・非表示を切り替えます。通信先ごとの量は積み上げで描きます。
- 問い合わせは必ず mask-api を通し、伏せ字にします。PLAYBACK 中は期間の終わりを再生位置にします。
- 値がないときは 0 ではなく「—」と出します。
- 描画は SVG で、重いライブラリは使いません。静止画として描くので、LITE モードでもそのまま動きます。
- キーボードで操作でき、両テーマ・全画面幅・44px のタッチ目標・幅固定の数値欄の規則を守ります。
- 問い合わせの組み立てはサーバー側の型 (テンプレート) で行います。クライアントから PromQL は受け取りません。

### 2. ログ検索の画面

- 絞り込みの条件は次のとおりです。
  - 機器、重要度、facility (syslog から取れたもの)
  - 語句 (部分一致。正規表現も選べ、長さと形に制限あり)
  - 期間 (Loki の保存期間まで)
- 結果は新しい順に 1 ページずつ読み、一致した部分に印を付けます。
- 期間の中の件数を、時間ごとの小さな棒グラフで示します。
- 結果は伏せ字にします。LogQL は許可した項目だけからサーバーで組み立て、入力は文字列として扱います。危ない正規表現は受け付けません。
- 問い合わせには時間と件数の上限を付けます。
- 選んだ行の時刻から、原因候補と証跡の出力へ進めます。

### 3. Grafana を任意にする

- compose の profile `grafana` を足し、demo と prod のどちらでも既定では動かしません。
- 動いていないとき、`/grafana/` は「有効になっていません」という 404 のページを返します。認証の規則、`tools doctor`、`tools check` は Grafana を求めません。
- 動かしたときは、今と同じ admin だけの扱いのままにします。
- `tools init / doctor / check / backup` は、どちらの状態でも正しく動くようにします。
- 既存の環境でも Grafana のデータ (grafana-data) を消しません。profile を有効にすれば、元のデータのまま使えます。doctor が「データが残っています、使うなら profile を足す」と案内します。
- 止めたことで減ったメモリを測ります。

### 4. 画面の開き方

- 上部バーには項目を足しません。
- 既存のパネルの見出しに開くボタンを置きます (WAN と接続口に「推移」、記録に「検索」)。
- 詳細のドロワーからも絞り込みを引き継いで開きます。
  - 機器と IF: 「推移を見る」「ログを検索」
  - 通信先と送信元: 「推移を見る」
  - syslog の行: 「ログを検索」

### 5. 試験

- mask-api の selftest で、型ごとの問い合わせと、語句・正規表現・範囲への注入の試みを拒むことを確かめます。
- 画面の確認スクリプトで、2 つの画面を確かめます。
- `scripts/verify.sh` の quick / e2e-open / e2e-auth が通ることを確かめます。
- 漏洩の検査 (leak-scan) で NG が 0 件であることを確かめます。

## 設計の要点

- 新しい読み取りの経路は `GET /trend/*` と `GET /logsearch/*` (mask-api、Caddy は GET / HEAD だけ通す) です。既存の `/prom/` `/loki/` と同じ伏せ字と literal の検査 (完全・部分アドレスの拒否、トークンの照合) を通します。
- 推移は `family` の名前と絞り込みの値だけを受け取ります。値は文字の種類と長さを決めて検査し、JSON の文字列としてラベルの一致 (`=`) に入れます。
- ログの語句と正規表現は、Loki には渡しません。伏せ字にした後の行に対して mask-api の中で照合します。生のアドレスを語句で探れないようにするためです。
- 正規表現は 64 文字までです。後方参照、先読み・後読み、量指定子の入れ子、繰り返しの中の選択は拒みます。長さの決まらない繰り返しは 1 か所、`?` はそれと一緒なら 1 か所までです。行は先頭の 1024 文字だけを照合し、一致した部分の印は照合の結果を使います (照合し直しません)。
- 件数の棒グラフは、語句がなければ Loki の `count_over_time` で数えます。語句があれば、新しい順に読める範囲で数え、上限に達したら「古い側は少なく出ている」と示します。
- Grafana が止まっているかどうかは、プロキシが Grafana に届かないこと (502) で判断し、`/grafana/` に限って 404 の案内を返します。

## 不変条件

- 伏せ字、認証と役割、Host の許可リスト (421)、PLAYBACK、PERF の挙動を変えません。
- 画面の規則 (情報の重複なし、幅固定、STALE と「—」、44px、両テーマ、全画面幅) を守ります。
- 既存のボリュームのデータを消しません。

## 検証の制約

- 使うコンテナは使い捨ての `obs-e2e-f1-*` だけにし、終わったら `down_project` で消します。main のプロジェクトには触れません。
- ブラウザは同時に 1 つだけ使います (browser.lock)。
