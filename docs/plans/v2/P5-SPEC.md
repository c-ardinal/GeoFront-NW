# P5 仕様: ネットワーク図と相関（原因候補）

親計画: `docs/plans/v2/PLAN.md`（承認済み。P4 は b923d19、PERF は 6335c68 で完了）

## 受入条件
1. **トポロジー図**: 地球儀の領域を「地球儀 / ネットワーク図」で切替（同じ位置・同じ大きさ。切替は既存の操作部に置き、上部バーに項目を増やさない。選択は localStorage、try/catch）
   - 構成は機器台帳（`inventory/devices.yaml`。必要なら親機器・接続 IF の任意項目を追加）から作る。SNMP で LLDP-MIB（lldpRemTable）が取れればその隣接で補い、出所（台帳 / LLDP）を線ごとに区別して表示する。RTX/WLX が LLDP を返すかは未確認のため、取れなくても台帳だけで成立すること
   - ノード: 機器名・種別・状態（UP/DOWN/STALE、既存の色と幅固定の規則）。線: 接続 IF、利用率（rate 2m）、エラー有無。WAN の先は「インターネット」ノード
   - クリックで既存の詳細ドロワー（機器・IF）を開く。キーボードで辿れる。PLAYBACK 中はその時刻の状態で描く
   - 描画は軽く（SVG か Canvas 2D、レイアウトは台帳順の決定的配置か一度だけ計算。毎フレームの再計算なし）。PERF の LITE モードでも同じ見た目で動く
2. **急増検出**: 端末（src_host）× 通信先（dst_country / asn）の通信量が平常より急に増えたものを検出（例: 直近 5 分の rate が過去 1 時間〜1 日の基準の N 倍かつ下限以上。閾値は `.env`）。Prometheus の記録ルールまたはクエリで行い、command-center で一覧表示。伏せ字は既存の規則どおり
3. **原因候補パネル**: アラート（ドロワー）・急増・選択した時刻を起点に、前後の時間窓（既定 ±10 分）で同時期に起きたことを時系列に並べる: 他のアラート（発火・解消）、関連機器の syslog（伏せ字済み）、IF の状態変化・エラー、急増、通知記録
   - 「相関の候補」であり因果は断定しない旨を常に表示。並べ順は時刻と関連度（同じ機器・同じ IF・同じ通信先）の簡単な規則で、規則を画面で説明できること
   - 各項目から該当の詳細・解析画面（P3、期間とフィルタを引き継ぐ）・証跡出力（P4、その時間窓）へ遷移
4. **API**: 読み取りのみ。mask-api の既存の読み取り経路と伏せ字を通す。重い問い合わせは上限・タイムアウト付き
5. **デモ**: demo profile で、DEMO_AUTO_FAULTS の障害と急増が図とパネルに現れる。testbed では snmpsim に LLDP の応答を足して隣接の取得経路を検証する

## 不変条件
- 既存の画面規則（重複なし・幅固定・STALE と —・44px・キーボード・両テーマ・全画面サイズ・eva-film のフォント）
- 伏せ字・書き込み制限・PLAYBACK・PERF の軽量化（30fps 上限、LITE、非表示時停止）を維持
- 機器の設定は変更しない（LLDP は読み取りのみ）

## 検証の制約（オーナー指示）
- コンテナは確認時のみ起動・終了後停止、ブラウザは同時 1 つ（browser.lock）。計測や確認は短時間・逐次
