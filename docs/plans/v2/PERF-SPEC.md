# PERF 仕様: Raspberry Pi 向け軽量化と表示側 GPU 活用

親計画: `docs/plans/v2/PLAN.md`（P4 完了後・P5 の前に実施。オーナー指示 2026-10-26）

## 前提
- 本番ホストは Raspberry Pi 4（4GB）級。この開発 PC よりも圧倒的に非力
- 表示側（ブラウザ）は GPU があればハードウェアアクセラレーションを使い、CPU 負荷を下げる。GPU がなければ自動で軽量表示に落とす

## 受入条件
1. **計測を先に行う（変更前の基準値）**
   - サーバ側: compose に Pi 相当の CPU とメモリの上限をかけた状態で、prod 相当（testbed 宛て）と demo のそれぞれを 10 分動かす。サービスごとの平均と最大の CPU・RSS を `docker stats` で採る
   - 表示側: WALLBOARD を 2 分表示したときのブラウザ CPU 時間・fps・メインスレッドの長いタスク。GPU 有り（ハードウェア）と無し（SwiftShader など）の 2 条件で採る
   - 結果は `docs/plans/v2/PERF-RESULTS.md` に変更前・変更後の表で残す
2. **サーバ側の目標**（Pi 4 相当の上限下、prod と testbed、機器 3 台）: 全体の平均 CPU を 1 コア換算で 25% 未満（4 コア合計の 1/4 未満）、合計 RAM を 2.5GB 未満にする
   - `OBS_PROFILE_LITE`（または pi 向けの既定値）: scrape と評価の間隔を 30s、Grafana は任意（無効でも command-center は動く）、Loki/Prometheus のキャッシュ・並列度・WAL を小さく、Alloy の処理を最小化
   - mask-api / flowd / analyzer の待機時のコストを小さくする（ポーリング間隔、キャッシュ、アイドル時に CPU を使わない）
   - 既定の上限値（`.env`）を計測結果に合わせて見直す
3. **表示側: GPU の検出と自動切替**
   - WebGL の有無と、`WEBGL_debug_renderer_info` などによるソフトウェア描画（SwiftShader / llvmpipe / Software 等）の判定。ソフトウェア描画なら自動で軽量モード（静止した地球儀または平面地図、アニメーションなし）に切り替える
   - 現在の描画モード（GPU / 軽量）を設定メニューに表示し、手動でも切り替えられる（localStorage に保存）。上部バーには増やさない（重複なしの規則）
4. **表示側: GPU 有りでも CPU を使わない描画**
   - アークの流れ・パルスなどの動きはシェーダ側（uniform の時間だけ更新）で行い、毎フレームの JS 側の頂点更新をやめる
   - HTML ラベルの毎フレームの位置更新をやめる（WebGL 側のラベル、または移動時のみ更新）。描画呼び出しをまとめる
   - 描画は最大 30fps。変化がなく操作もないときは描画を止めるか間引く。タブ非表示時は止める（`visibilitychange`）
   - CSS アニメーションは transform / opacity のみ（合成処理だけで済むもの）。ticker・STALE などの既存演出は見た目を保つ。`prefers-reduced-motion` を尊重する
5. **取得の負荷とタイムアウト**: ポーリングの重複を排除（同じクエリを同じ周期で 1 回）。fetch にタイムアウトを付け、超過時は鮮度バッジを DEGRADED にする（幅固定の規則を維持）
6. **README**: Pi での推奨設定（lite の既定値）と、表示端末に Pi の Chromium を使う場合の GPU 設定の注意（ハードウェアアクセラレーションの確認方法、軽量モードへの切替）

## 不変条件
- 見た目・情報量・画面規則（重複なし・幅固定・STALE と —・44px・両テーマ・全画面サイズ）は変えない。軽量モードは同じ情報を静的に出す
- 伏せ字・書き込み制限・PLAYBACK の挙動（P1〜P4）を維持する

## 検証の制約（オーナー指示）
- コンテナは計測時だけ起動し、終わったら停止する。ブラウザは同時に 1 つ（browser.lock）
- この PC に負荷をかけすぎない。計測は条件ごとに短時間・逐次で行う
