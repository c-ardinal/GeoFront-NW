## 受入条件
1. **通知記録のアドレス識別子（N3）**
   - notify-relay が残す通知記録（Loki に送るもの・画面・原因候補・証跡に出るもの）で、ラベル値の完全なアドレスは mask-api と同じ方式・同じ鍵の識別子（トークン）にする。今は x に潰しているため、同じ機器・通信先を画面の他の場所と突き合わせられない
   - 自由文は今の形だけ残す規則（a.b.c.x など）を維持。通知先へ送る本文の伏せ字は変えない（外部へ送る本文に識別子を出すかは現状どおり）
   - 識別子の鍵は既存の秘密値を共有し、新しい秘密値を増やさない。鍵が無いときは x に潰す（fail-closed）
   - 原因候補（P5）で、通知記録が同じ機器・同じ通信先として関連付けられることを確認する
2. **画面スナップショット（PNG）**
   - 証跡出力（P4）に「画面のスナップショットを含める」選択肢を付ける（既定はオフ）。ブラウザ内で生成した PNG を zip に `snapshot.png` として含め、manifest に「ブラウザで生成」と sha256 を記録する
   - 地球儀（WebGL）と通常の画面要素の両方が写ること。新しい外部ライブラリは原則足さない（足す場合は理由と版固定）
   - 写るのは既に伏せ字済みの画面だけ。ファイル名・メタデータにアドレスを入れない。生成できない環境では理由を表示して PNG なしで出力を続ける
   - サーバへの書き込み経路を増やす場合は、既存の書き込み制限（127.0.0.1 公開時のみ・Host/Origin/CSRF）に従う。LAN 公開時の挙動を README に書く

## 不変条件
- 伏せ字・書き込み制限・PLAYBACK・PERF・P5 の挙動、既存の画面規則（重複なし・幅固定・STALE と —・44px・両テーマ・全画面サイズ）を維持
